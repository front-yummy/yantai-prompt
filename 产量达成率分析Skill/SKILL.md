# 产量达成率分析

⚠️ 输出总纲(最高优先级,必须遵守)
最终只输出一份"产量达成率分析报告"文档(Markdown),禁止输出任何其他内容。
- 禁止输出:流程回顾、各步骤中间结果、推理过程、调用说明、执行顺序、字段解释、思考过程、复述输入
- 禁止输出:中间 JSON(step1_result/step3_result 等不得出现在最终输出里)
- 内部推理在心里完成,不要落到输出里
- 唯一允许的非文档输出:当某步骤因数据异常无法继续(见各步骤的"终止条件")时,只输出一句提醒文字说明卡在哪,不输出报告
- 步骤7的"询问用户是否触发事件中心"是交互动作,不属于最终报告输出,单独在报告之后提问

# 这个 skill 解决什么问题
现场要回答"这段时间计划达成率达标了没,没达标是哪类损失(人/机/料/品)造成的,哪条线损失最大,谁负责,怎么改,对后工序有什么影响"。本 skill 把查询、归因、责任匹配、改善对策、影响预测串成一条链,直接给一份完整报告,并支持用户确认后推送事件中心。

# 依赖(子skill / MCP)
- 子skill「维度识别Skill」(见 README 子skill 清单):把(时间、组织、分析维度、分组、指标ID)组装成 IOC 指标入参 JSON,含 startTime/endTime/analyseDimList/orgDimList/groupBy 等。
- MCP「指标数据检索MCP」:按入参查单个指标汇总数据。入参结构 = 子skill「维度识别Skill」的输出 JSON。本 skill 把子skill 输出原样透传给该 MCP,不重命名/不改类型/不补字段。
- MCP「达成率损失数据检索MCP」:一次查询全部二级损失类型(人机料品)按线体分组的损失工时与损失产量,并返回损失明细(all)和帕累托分析(top1)结果。入参结构见步骤3。
- 子skill「生产损失归因Skill」:根据一级/二级损失类型,输出原因及改善措施。
- 子skill「制程损失责任自动匹配」:根据损失分析数组(制程/线体/一级/二级)匹配责任人。
- 子skill「生产达成率后续影响Skill」:针对后工序的影响预测,仅 SMT 制程触发。
- 子skill「产量推送事件中心skill」:将匹配结果推送至事件中心。

# 输入
- 用户时间表达(如"2026年7月""本周")
- 用户组织值(如"NME厂""ASSY制程")
- 用户分析值(如某机种)

说明:group(分组维度)和 indexId(指标ID)由本 skill 内部按步骤固定传给子skill,不取用户值。

# 通用原则
1. 透传边界:透传只发生在"子skill 输出 -> MCP/子skill 入参"那一刻,原样透传,严禁字段重命名、类型转换、结构简化、值格式化或缺失字段补全。结构不一致则终止流程并返回错误,不自行适配。skill 内部的删字段、取值、判断达标、组装数组等是本 skill 自己的计算逻辑,不受透传约束。
2. 损失产量:以 MCP 返回值为准,skill 不自行计算。MCP 返回 0 或缺失则报告不展示该列,有非0数据时展示。
3. 字段语义:typeTwoLine = 线体编号(groupName);typeTwoRate(all中) = 二级占一级的比例,必须输出。
4. 步骤6仅当制程为 SMT 时执行,否则跳过。
5. 步骤2达标(>=100%)则直接结束,不执行后续步骤。

# 处理流程(内部执行,不输出,按步骤循序严格串行执行)

步骤1: 解析公共维度参数
调用子skill「维度识别Skill」,arguments:
- time = 用户时间值
- org = 用户组织值
- analysis = 用户分析值
- group = 线体(固定)
- indexId = 2054755021069975554,2061719849122734081,2062087079997796353,2056309325596848130,2056285219967070209,2056664748459945986,2062346129780043778,2061341971726016513,2062346430297731073
输出:step1_raw(JSON 对象,含 dateDim/startTime/endTime/dimType/groupByDim/dimensionId/orgDimList/analyseDimList/indexId 等)。
处理:删除 step1_raw 中的 indexId 字段,剩余所有字段记为 step1_result(含 startTime/endTime/dimType/groupByDim/dimensionId/orgDimList/analyseDimList 等,不含 indexId)。

步骤2:查询计划达成率并判断
调用 MCP「指标数据检索MCP」,arguments 必须为(公共字段从 step1_result 提取,indexId 单独填):
- dateDim = step1_result.dateDim
- startTime = step1_result.startTime
- endTime = step1_result.endTime
- analyseDimList = step1_result.analyseDimList
- orgDimList = step1_result.orgDimList
- dimType = "组织维度"
- groupByDim = step1_result.orgDimList[0].orgDimName
- dimensionId = step1_result.dimensionId
- indexId = 2054755021069975554(计划达成率)
输出:step2_result(取 actualValue = 计划达成率值)。
判断:
- actualValue >= 100% -> 输出"计划达成率达标(达 xx%),无需分析" -> 终止,不再执行后续步骤。
- actualValue < 100% -> 继续 步骤3。
终止条件:若 step2_result 为空或 actualValue 缺失,输出提醒"在指定条件下未查到计划达成率数据,请检查时间/组织/分析维度是否有效",不再继续。

步骤3:损失工时归因与损失产量

调用 MCP「达成率损失数据检索MCP」,查询8个二级损失类型(人机料品)按线体分组的损失工时与损失产量,返回帕累托分析(all)和top1结果。

3.1 构造入参
入参为如下 JSON 结构(equip/person/material/quality 为固定的人机料品指标信息,param 为 step1_result 透传):

```json
{
  "equip": [
    { "type": "停线", "indexId": "2056309325596848130" }
  ],
  "person": [
    { "type": "爬坡", "indexId": "2061719849122734081" },
    { "type": "切换线", "indexId": "2062087079997796353" }
  ],
  "material": [
    { "type": "来料异常", "indexId": "2056285219967070209" },
    { "type": "物料验证", "indexId": "2056664748459945986" }
  ],
  "quality": [
    { "type": "重投", "indexId": "2062346129780043778" },
    { "type": "重工", "indexId": "2061341971726016513" },
    { "type": "复测", "indexId": "2062346430297731073" }
  ],
  "param": "<step1_result 原样透传,不含 indexId>"
}
```

equip/person/material/quality 的 type 与 indexId 固定使用上述值,不得改动。

3.2 调用 MCP 并接收结果
调用 MCP「达成率损失数据检索MCP」,arguments = 3.1 构造的入参。
输出:step3_result,含两个字段:
- all:数组,全部二级损失类型指标的损失工时、损失产量、二级在一级中的占比。每项字段:
  - typeOne:一级类型(人力/设备/物料/品质)
  - typeOneHour:一级类型总工时
  - typeOneRate:一级类型占总损失的比例
  - typeTwo:二级类型(爬坡/切换线/停线/来料异常/物料验证/重投/重工/复测)
  - typeTwoLine:线体编号(针对 all 分析后的线体)
  - typeTwoHour:二级类型工时
  - typeTwoRate:二级类型占该一级类型的比例
  - 损失产量:由 MCP 返回,字段名以 MCP 实际返回为准
- top1:数组,一级帕累托分析结果 + 对应 top1 二级 + 二级下 top1 线体的损失。每项字段同 all,其中 typeTwoLine 为该一级类型下损失最高的线体编号。

3.3 提取分析结果
从 step3_result 中提取,供后续步骤使用:
- 损失明细表数据:从 all 中取,展示全部一级/二级损失类型,每行含 一级类型/一级占比(typeOneRate)/二级类型/二级工时(typeTwoHour)/二级占一级比例(typeTwoRate)。同一二级类型下多条线体的工时合并求和,不展示线体编号。损失产量列仅当 MCP 返回非0时展示,为0或缺失则不展示。
- 重点线体:从 top1 中取,每条 top1 对应一个一级类型,其 typeTwoLine 为该一级类型下最高损失线体,typeTwo 为对应二级类型。

步骤4:制程损失责任匹配
针对步骤3分析出的 top1 损失,匹配相应责任人。

4.1 构造损失分析数组:遍历 step3_result.top1,每项必须包含四个字段:

```json
[
  {
    "制程": "<从 step1_result.orgDimList 中制程维度条目的 orgDimNameValues 取值>",
    "线体编号": "<step3_result.top1 中的 typeTwoLine>",
    "一级损失类型": "<step3_result.top1 中的 typeOne>",
    "二级损失类型": "<step3_result.top1 中的 typeTwo>"
  }
]
```

   制程字段取值 = step1_result.orgDimList 中 dimType/levelName 为制程(製程)的条目的 orgDimNameValues(若为多值数组取第一个或拼接)。若用户原始组织值中未含制程,制程字段填 ""。

4.2 调用子skill「制程损失责任自动匹配」,必须按以下入参格式传入:

```json
{
  "损失分析数组": "<上述构造的数组>",
  "时间值": "<时间值>",
  "组织值": "<组织值>",
  "分析值": "<分析值>"
}
```
输出:匹配结果数组(含责任人信息),供步骤5和步骤8使用。

步骤5:原因及改善对策分析
调用子skill「生产损失归因Skill」,传入 step3_result.top1 中的一级类型和二级类型(只针对帕累托分析出的重点损失,不是全部人机料品),责任人取步骤4的匹配结果。
输出:原因及改善措施(含责任人)。

步骤6:后工序影响预测
判断:从 step1_result.orgDimList 中查找"制程"维度条目(orgDimName 含"製程"或"制程"),取其 orgDimNameValues。
- 若制程值为 "SMT" -> 执行本步骤。
- 否则 -> 跳过本步骤,报告不输出风险预警节。
执行:调用子skill「生产达成率后续影响Skill」,入参必须包含:
- time = 用户时间值
- org = 用户组织值
- analysis = 用户分析值
输出:对后工序的影响结果。

步骤7:整合输出报告
将步骤2~6的结果整合为 Markdown 报告,格式见示例。报告含五节:总体情况、损失明细、帕累托归因分析、改善对策及责任人、风险预警(仅当步骤6执行时输出)。

步骤8:询问并推送事件中心
在输出报告后,询问用户:"是否需要自动触发事件中心,将本次损失分析及责任信息推送至相关责任人?"

若用户肯定,调用子skill「产量推送事件中心skill」,必须按以下入参格式传入:

```json
{
  "损失分析数组": "<步骤4返回的完整匹配结果数组>",
  "时间值": "<用户时间值>",
  "组织值": "<用户组织值>",
  "分析值": "<用户分析值>"
}
```

返回推送结果(成功/失败信息),并告知用户,简要汇总(如成功匹配几条、失败几条)。

若用户否定或超时:不触发事件,结束流程,仅保留已输出的报告。
