# 设备异常分析

⚠️ 输出总纲(最高优先级,必须遵守)
最终只输出一份"设备异常分析结果"文档(Markdown 表格),禁止输出任何其他内容。
- 禁止输出:流程回顾、各步骤中间结果、推理过程、调用说明、执行顺序、字段解释、思考过程、复述输入
- 禁止输出:中间 JSON(step1_result/step2_result 等不得出现在最终输出里)
- 内部推理在心里完成,不要落到输出里
- 唯一允许的非文档输出:当某步骤因数据异常无法继续(见各步骤的"终止条件")时,只输出一句提醒文字说明卡在哪,不输出表格

# 这个 skill 解决什么问题
现场要回答"这段时间哪条线故障最多、那条线哪几台设备故障最多、这些设备停了多久"。手动要查两次故障指标 + 一次停机指标 + 自己挑 Top3 + 合并,链路长。本 skill 把这条链路串起来,直接给一张"线体下 Top3 故障设备 + 计划外停机时长"的明细表。

# 依赖(平台自动触发 / 子skill / MCP)
- 子skill「维度识别Skill」(见 README 子skill 清单):把(时间、组织、分析维度、分组、指标ID)组装成 IOC 指标入参 JSON,含 startTime/endTime/analyseDimList/orgDimList/groupBy 等。本 skill 调用它时只传 5 个 arguments,维度元数据由该子skill 自己取,本 skill 不干预。
- MCP「指标数据检索MCP」:按入参查指标汇总数据。入参结构 = 子skill「维度识别Skill」的输出 JSON。本 skill 把子skill 输出原样透传给该 MCP,不重命名/不改类型/不补字段。

# 输入
- 用户时间表达(如"2026年7月""本周""上个月""2026-06-01到2026-06-26")
- 用户组织值(如"NME厂""ASSY制程")
- 用户分析值(如"TNS-L側蓋FPC基板前加工机种")

说明:group(分组维度)和 indexId(指标ID)由本 skill 内部按步骤固定传给子skill,不取用户值。

# 数据透传原则(重要,先看)
透传只发生在"子skill 输出 -> MCP 入参"这一刻:子skill 返回的 JSON,作为 MCP arguments 时必须原样透传,严禁字段重命名、类型转换、结构简化、值格式化或缺失字段补全。若 MCP 要求的入参与子skill 输出结构不一致,终止流程并返回错误,不得自行适配。

skill 内部的步骤处理不受此约束:提取最大值、排序取 Top3、合并两个结果集、补 0 等,是本 skill 自己的计算逻辑,允许取值/赋值/补全,不违反透传原则。

# 固定常量
| 常量 | 值 | 含义 | 用于步骤 |
|---|---|---|---|
| 指标A:故障次数 | 2056308992057405441 | 故障次数指标ID | 步骤1、4 |
| 指标B:计划外停机时长 | 2056309325596848130 | 计划外停机时长指标ID | 步骤6 |
| 分组:线别 | 線別 | 按线体分组 | 步骤1 |
| 分组:设备 | 设备名称 | 按设备分组 | 步骤4、6 |

为什么步骤6要换 indexId:步骤1/4 查的是"故障次数"指标(指标A),步骤6/7 查的是"计划外停机时长"指标(指标B),两者是不同指标,必须用对应指标ID。混用会拿到错的指标值。

# 处理流程(内部执行,不输出)

步骤1:组装"各线体故障次数"入参
调用子skill「维度识别Skill」,必须包含如下arguments：
- `time` = 用户时间表达
- `org` = 用户组织值
- `analysis` = 用户分析值
- `group` =  `線別`（固定值）
- `indexId`=  `2056308992057405441`（固定值，故障次数）
输出:step1_result(JSON 对象)。

步骤2:查各线体故障次数
调用 MCP「指标数据检索MCP」,arguments 必须为 step1_result 原样透传(遵循数据透传原则)。
输出:step2_result(JSON 数组,每项含 actualValue=故障次数、groupByName=线体名)。
终止条件:若 step2_result 为空数组或全部 actualValue 为 0,输出提醒"在指定条件下未查到任何线体故障数据,请检查时间/组织/分析维度是否有效",不再继续。

步骤3:定位故障次数最高的线体
从 step2_result 中取 actualValue 最大的项 -> max_item。
- target_line = max_item.groupByName
- target_line_value = max_item.actualValue
并列最大取第一项,记录线体名即可。

步骤4:组装"目标线体各设备故障次数"入参
调用子skill「维度识别Skill」,arguments:
- `time` = 用户时间表达
- `org` = target_line(步骤3 的线体)
- `analysis` = 用户分析值
- `group` = 设备名称（固定值）
- `indexId` = `2056308992057405441`（固定值，故障次数）
输出:step4_result(JSON 对象)。

步骤5:查目标线体各设备故障次数 -> 取 Top3
调用 MCP「查指标数据-按时间汇总V2」,arguments 必须为 step4_result 原样透传。
输出:fault_result = [{"actualValue": 故障次数, "groupByName": 设备名称}, ...]
处理:按 actualValue 倒序,取前3条 -> top3_fault,并提取设备名称列表 top3_device_names。
终止条件:若 fault_result 为空,输出提醒"线体{target_line}未查到设备级故障数据",不再继续。
不足3个的处理:若设备不足3个,有几个取几个,top3_device_names 就是实际取到的列表。

步骤6:组装"Top3设备计划外停机时长"入参
调用子skill「维度识别Skill」,arguments:
- `time` = 用户时间表达
- `org` = target_line(步骤3 的线体)
- `analysis` = 用户分析值 + 设备名称为 top3_device_names(步骤5)
- `group` = 设备名称(固定值)
- `indexId` = `2056309325596848130`（固定值,计划外停机时长,注意与步骤1/4 不同)
输出:step6_result(JSON 对象)。

步骤7:查 Top3 设备的计划外停机时长
调用 MCP「指标数据检索MCP」,arguments 必须为 step6_result 原样透传。
输出:downtime_result = [{"actualValue": 计划外停机时长, "groupByName": 设备名称}, ...]

步骤8:合并并生成最终输出
- 以设备名称为键,合并 top3_fault 和 downtime_result:
  - 设备的故障次数取自 top3_fault
  - 设备的停机时长取自 downtime_result 中同名设备;若某设备在停机结果中缺失,downTime 填 0
- 按 top3_fault 的原顺序输出(即故障次数倒序),不因停机时长重排
- 停机时长单位:小时(若 MCP 返回的是分钟或其他,按小时换算:分钟/60;若返回已是小时则直取)

# 输出格式(再次强调)
- 只输出一份 Markdown 文档,结构见示例
- 标题"设备异常分析结果"
- 分析时间范围:从 step1_result 的 startTime/endTime 取(或直接用用户时间表达)
- 故障次数最高的线体 + 次数
- Top3 设备明细表:设备名称 / 故障次数 / 计划外停机时长(小时)
- 不足3台设备时,表格按实际行数输出,不补空行
- 唯一例外:某步骤触发终止条件时,只输出一句提醒文字,不输出表格
