## [2026-08-12] v1.11 修复 mcp 不返回星期几导致的编码错位

**问题:**
v1.10 的公式和例子都正确,但模型仍把上周算成 08-04~08-10(整体晚1天)。拿到 mcp 真实返回后发现根因:
mcp(system_time) 返回 {"datetime": "...+08:00", "timezone": "CST", "unix_timestamp": ...},**根本没有星期几字段**。模型只能自己从日期推星期,推时用了 JS getDay()(周日=0),导致星期三被当成星期二,整体偏移1天。
v1.10 之前那段"读时区字段...直接用 ISO 时间的星期几"是错的--ISO 时间里就没有星期几。

**改动点:**
- 依赖节写明 mcp 真实返回格式(datetime/timezone/unix_timestamp 三字段),明确"mcp 不返回星期,需自己从日期判断"
- 日期取法:直接取 datetime 前10位(已带 +08:00),不用 unix_timestamp 反推
- 星期几:钉死 ISO 编码(周一=1...周日=7),明确禁止 JS getDay(),点明"那是上周算错1天的根源"
- 加锚点校验:2026-01-01 是星期四,用日期差 mod 7 推星期几并自检(例:2026-08-12 距 01-01 = 223天,223 mod 7 = 6,星期四+6=星期三)

**原因:**
之前不知道 mcp 真实返回格式,写的规则基于"返回里有星期几"的错误假设。拿到真实返回后,问题从"怎么读星期"变成"怎么自己算星期且不踩 getDay 坑"。锚点校验让模型有自检机会。

**测试结论:** 待平台覆盖后用"上周"复测,重点验 start=08-03、end=08-09。

## [2026-08-12] v1.10 修复"上周"整体晚1天

**问题:**
v1.9 公式正确(上周=08-03~08-09),但模型实际输出上周=2026-08-04~2026-08-10,整体晚1天。根因:模型把星期三取成了星期二(星期几=2 而非 3),导致本周一算成 08-11,上周一算成 08-04,上周日算成 08-10。

**改动点:**
- 把"星期一=1...星期日=7"展开成完整映射(星期一=1,星期二=2,星期三=3,...),消除编码歧义,避免模型用 JS(周日=0)导致整体偏移
- 公式结构改为"先定本周一"再派生本周/上周,本周一作为唯一锚点
- 加校验句:上周 end 必须早于本周 start,且上周 end 不是今天--给模型一个自检锚点,算错时能自己发现

**原因:**
文档公式对、模型算错,说明不是公式问题而是星期编码被误解。展开编码 + 加自检校验,用最小改动堵住偏移。

**测试结论:** 待平台覆盖后用"上周"复测,重点验 start=上周一、end=上周日且 end<本周一。

## [2026-07-28] v1.0 初始优化版(从原版重构)

**改动点(相对用户提供的原版):**

1. **时间解析补全**:原版只列了"2026年7月/本周/今天"几个例子,补充相对表达(本周/上个月/最近一周)的 start/end 推算规则;明确"本周 end=今天"(工业数据避免未来空数据);明确依赖"获取当前系统时间 skill"拿基准时间(仅相对时间触发,绝对时间不触发)。
2. **时间粒度校验**:明确"推断粒度必须命中 `timeParticleList`,不在则提醒用户并终止";明确 `timeParticleList` 不可能为空。
3. **字段命名统一**:原版前后矛盾(timeParticle/startDate vs dateDim/startTime),统一为 `dateDim/startTime/endTime`。
4. **组织维度匹配重构**:从"遍历所有组织维度条目、每条都输出(空填 [])"改为"语义识别维度词 -> 定位条目 -> 值匹配 -> 只输出命中条目";新增内置值表(ASSY/DIP/INJ/PAI/SMT/STA->製程;NME->廠別)辅助语义识别;新增"多值命中同一条目合并为一个值数组"规则。
5. **分析维度**:同组织维度逻辑,无分析维度时 `analyseDimList` 为 `[]`。
6. **分组维度 fallback 明确**:用户没说分组或匹配不到时,fallback 到第一个组织维度条目,`groupByDimValue` 固定为 `""`。
7. **同义词映射讲清逻辑**:明确"匹配不到才归一化"的兜底设计 + 为什么(简写 vs 繁体规范名)。
8. **调用方式**:MCP 维度查询每次必先调用(选 B 方案,skill 主动调);子skill 仅相对时间触发;调用话术由平台触发(选 B,不输出话术)。
9. **输出要求**:只输出 JSON,唯一例外是需客户补充信息时输出提醒文字。

**原因:**
原版存在字段命名矛盾、时间解析不全、组织维度匹配逻辑模糊(遍历导致一堆空条目)、同义词表缺机种等问题,实测输出含大量空条目和推理过程。全面重构以达"只输出精简 JSON"目标。

**遗留待确认:**
- 分组 fallback 到"第一个组织维度条目",不同测试数据下该条目可能不同(L0 全球 / L1 基地),属正常,非 bug。
- 分析维度 `dimNameValueList` 实际存的是"AA"(不带"机种"后缀),故"裁掉机种后缀再匹配"规则正确,无需改。
