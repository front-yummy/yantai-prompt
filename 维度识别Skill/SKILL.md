# 输出总纲(最高优先级,必须遵守)
最终只输出一个 JSON 对象,禁止输出任何其他内容。
禁止输出:解析过程、推理步骤、调用说明、执行顺序、字段解释、思考过程、复述输入。
禁止输出:json 代码块标记以外的任何文字(连"输出:""结果:"都不要)。
唯一允许的非 JSON 输出:当需要客户补充信息时(时间粒度不在列表 / 时间范围无法解析),只输出一句提醒文字,不输出 JSON。
内部推理在心里完成,不要落到输出里。

# 这个 skill 解决什么问题
用户用自然语言说"查询NME厂、ASSY制程、2026年6月的产量,按线体分组",而 IOC 指标接口需要的是结构化 JSON 入参。本 skill 把"自然语言 + 指标ID"翻译成标准入参 JSON。

# 输入
- 用户时间表达(如"2026年7月""本周""上个月")
- 用户组织值(如"NME厂""ASSY制程")
- 用户分析值(如"TNS-L側蓋FPC基板前加工机种")
- 用户分组值(如"按线体分组")
- 指标 ID(字符串,数字和逗号组成,直传不解析)

# 处理流程(内部执行,不输出)

0. 取维度元数据
通过 MCP 用指标 ID 查维度元数据,后续步骤都基于返回的 payload。
指标 ID 为外部传入的逗号隔开字符串(可能含多个ID),必须作为完整字符串一次性传给 MCP,严禁拆分成多个ID分别调用或并行调用。MCP 支持逗号隔开的多指标ID查询,一次调用返回全部维度元数据。
payload 结构:
{
  "code": 0,
  "payload": {
    "timeParticleList": ["日","周","月","年"],
    "indexDimDetailDTOList": [
      {
        "dimType": "组织维度|分析维度",
        "dimensionId": "",
        "levelCode": "",
        "levelName": "",
        "dimCode": "",
        "dimName": "",
        "dimNameValueList": []
      }
    ]
  }
}
- timeParticleList:纯字符串数组,不可能为空
- dimNameValueList:纯字符串数组,如 ["NME","ASSY"]

1. 时间维度

(1) 判断是否需要基准时间
用户表达含相对时间词(今天/本周/上个月/最近N天等)时,调用 mcp(system_time),传入参数"获取当前日期和星期";绝对时间(如2026年7月、2026-06-01到2026-06-26)直接解析,不调用。

mcp(system_time) 返回服务所在机器的 ISO 时间 + 时区 + Unix 时间戳(三者都给,机器时区不固定)。返回格式示例:{"datetime": "2026-08-12T13:03:12.052943+08:00", "timezone": "CST", "unix_timestamp": 1786510992}。datetime 已带 +08:00 东八区时区,直接取前10位作今天日期(如 2026-08-12),不要用 unix_timestamp 反推日期。
星期几:mcp 不返回星期,需自己从日期判断。用 ISO 编码:星期一=1、星期二=2、星期三=3、星期四=4、星期五=5、星期六=6、星期日=7。禁止用 JS getDay()(周日=0),那是上周算错1天的根源。
锚点校验:2026-01-01 是星期四。算今天距 2026-01-01 的天数差,除以7取余推星期几。例:2026-08-12 距 2026-01-01 = 223天,223 mod 7 = 6,星期四+6 = 星期三,星期几=3。

(2) 推断时间粒度
按"能解析到的最大粒度"取,优先级 年 > 月 > 周 > 日:

| 用户表达 | 粒度 | start | end |
|---|---|---|---|
| 2026年 | 年 | 2026-01-01 | 2026-12-31 |
| 2026年7月 | 月 | 2026-07-01 | 2026-07-31 |
| 本周 | 周 | 本周一 | 今天 |
| 上周 | 周 | 上周一 | 上周日 |
| 今天 | 日 | 今天 | 今天 |
| 上个月 | 月 | 上月1号 | 上月最后一天 |
| 最近一周 | 日 | 今天-6 | 今天 |
| 2026-06-01到2026-06-26 | 日 | 2026-06-01 | 2026-06-26 |

粒度判断:含"年"且无月/日 -> 年;含"月" -> 月;"本周/这周/上周" -> 周;"今天/最近N天/具体日期范围" -> 日

相对时间推算(用步骤1取到的"今天日期 + 星期几"):
先定本周一:本周一 = 今天 - (星期几 - 1) 天,其中星期一=1,星期二=2,星期三=3,星期四=4,星期五=5,星期六=6,星期日=7。
本周:start = 本周一,end = 今天(不取本周日)。
上周:start = 本周一 - 7 天(上周一),end = 本周一 - 1 天(上周日,完整自然周,不截到今天)。

举例(今天=2026-08-12 星期三,星期几=3):
本周一 = 2026-08-12 - (3-1) = 2026-08-10
本周 = 2026-08-10 ~ 2026-08-12
上周一 = 2026-08-10 - 7 = 2026-08-03;上周日 = 2026-08-10 - 1 = 2026-08-09;上周 = 2026-08-03 ~ 2026-08-09

校验:上周 end 必须早于本周 start(上周日 < 本周一),且上周 end 不是今天。

(3) 校验粒度必须命中 timeParticleList
推断出的粒度若不在 timeParticleList 中,只输出提醒:"时间粒度'{粒度}'不在指标支持范围内(支持:{列表}),请调整时间表达",不再输出 JSON。

(4) 若无法解析出 start 或 end(用户表达太模糊)
只输出:"请补充查询时间范围(如:2026-06-01到2026-06-26)",不再输出 JSON。

输出字段:dateDim(粒度名)、startTime、endTime。

2. 指标 ID
直接使用外部传入值,字符串格式,填入 indexId。若传入的是逗号隔开的多个ID,原样输出逗号字符串,不拆分。

3. 组织维度(orgDimList)
对用户每个组织值,识别其所属维度,在 dimType=="组织维度" 条目中定位并匹配。匹配不到的值不产出条目。

识别维度:语义识别用户值属于哪个维度(廠別/製程/線別/棟別/...)。辅助依据:
- 后缀词:厂/车间/楼栋/制程/线/线体/机种/品牌
- 内置值表:ASSY/DIP/INJ/PAI/SMT/STA->製程;NME->廠別

定位条目:对识别出的维度词做同义词归一化(见第6节),在组织维度条目中按 levelName 匹配。多条命中则全部作为候选。

匹配值:用用户值(裁掉维度词后)在候选条目的 dimNameValueList 中查找,命中第一条即止,只输出这一条。匹配不到则该值不产出条目。

合并:多个用户值命中同一条目时,合并为一条,orgDimNameValues 汇总所有命中值(去重)。如 ASSY、DIP 都命中 L3 製程,输出一条 orgDimNameValues:["ASSY","DIP"]。

填充字段(从命中条目复制):levelCode、dimensionId、orgDimCode(=dimCode)、orgDimName(=dimName)、orgDimNameValues(命中值数组)。

为什么这样设计:先靠维度词把范围缩到一类维度,再用值在这类维度的条目里精确命中,避免把值误填到无关层级。多个同 levelName 的条目靠值的 dimNameValueList 自然区分。

4. 分析维度(analyseDimList)
逻辑同组织维度(语义识别维度 -> 定位条目 -> 匹配值 -> 合并),在 dimType=="分析维度" 条目中处理。若无分析维度条目,analyseDimList 为 []。

填充字段:levelCode、dimensionId、analydim(=dimName)、analydimValues(命中值数组,多值合并去重)。

例:"TNS-L側蓋FPC基板前加工机种"->语义识别维度"机种"->裁值得"TNS-L側蓋FPC基板前加工"->在分析维度条目匹配。

5. 分组维度(顶层字段,必填)
用户分组值 = 用户表达中"按…分组"里的那个词。

(1) 归一化 + 匹配
对用户分组值做同义词归一化,然后在整个 indexDimDetailDTOList(不限 dimType)中查找 levelName 与归一化后的值不区分大小写完全匹配的条目。多个命中取第一个。

(2) 匹配成功,填充:
- dimType = 匹配条目的 dimType
- groupByDim = 匹配条目的 dimName
- dimensionId = 匹配条目的 dimensionId
- levelCode = 匹配条目的 levelCode
- groupByDimValue = 用户若指定了具体分组值(如"按机种A"中的"A"),填入;否则 ""

(3) 未匹配成功(用户没说分组,或分组词匹配不到),fallback 到第一个 dimType == "组织维度" 的条目:
- groupByDim = 该条 dimName
- groupByDimValue = ""(固定)
- dimType、levelCode、dimensionId:直接复制

6. 同义词映射(全局,用于组织/分析/分组)
目的:增加匹配命中率。注意:如果用户原词(或裁剪后的值)已经能直接匹配,就不归一化;只有匹配不到时,才用同义词再试一次。映射如下:

| 用户常用词 | 归一化为 |
|---|---|
| 厂 | 廠別 |
| 车间 / 楼栋 | 棟別 |
| 制程 | 製程 |
| 线 / 线体 | 線別 |
| 机种 | 機種 |
| 品牌 | 厂牌 |
| 产品编码 | 产品料号 |

为什么这样设计:工业现场用户习惯用简写(厂/制程/线体/机种),但维度元数据里存的是繁体规范名(廠別/製程/線別/機種)。归一化是"匹配不到时的兜底",不是强制转换,避免误伤已经能直接命中的表达。

7. 匹配策略总则
- 不区分大小写
- 优先 levelName 完全匹配,否则包含匹配
- 多个命中取第一个

# 输出格式(再次强调)
- 只输出一个 JSON 对象,从 { 开始,到 } 结束,前后无任何文字
- 所有字段必须存在,无法提取或匹配的用 "" 或 []
- orgDimList / analyseDimList 只输出匹配到的条目,匹配不到直接 [],不输出空条目
- 字段保持一致:组织维度条目统一输出 levelCode/dimensionId/orgDimCode/orgDimName/orgDimNameValues,不输出多余字段
- 唯一例外:需客户补充信息时(时间粒度不在列表 / 时间范围无法解析),只输出一句提醒文字,不输出 JSON

输出字段顺序:dateDim、startTime、endTime、indexId、levelCode、dimType、groupByDim、dimensionId、groupByDimValue、orgDimList、analyseDimList
